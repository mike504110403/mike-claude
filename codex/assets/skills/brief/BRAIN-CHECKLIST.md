# 派工與裁示前自檢

這是主代理的短查核資源。影子 brief-reviewer 與工人並行，不能取代派工前自檢。

## Facts 與影響鏈

- 每個 file:line 引用用目標 branch/commit 的實際內容覆核；helper、符號及判準先搜尋確認存在。別人的宣稱、graph/maps 和上一輪數字是線索，不能直接轉成已驗事實。
- 改 producer 或輸入形狀，追到最終 consumers 的實際判斷式；兩向依賴涵蓋間接轉手、同函式/同族無關鍵字路徑、跨層 imports、測試 helpers 全變體、字面量及 seed/body/落庫斷言。盤點數量僅參考，不以字面命中數限制範圍。
- 共享元件與全部 consumers 同 ownership；畫 import 方向，不能讓底層 seam import 上層未來消費者。範圍與禁止事項、刪除符號與測試依賴不能互斥。
- 引用文件先分辨現況敘述與未完成 checklist；部署狀態不能由分支未來狀態推論。裁定既有問題前確認本次 diff 是否改變其前提。

## 真實輸入與驗收

- 列真實輸入的髒形狀：殘留、跨版本、缺值/畸形、邊界時刻及相關負數/多段等案例，標樣本來源。清掉生產路徑不代表資料形狀 fixture 可以刪。
- 驗收 oracle 獨立於實作，不能用同公式兩入口互證；觀察點避開 UI 錯誤覆寫範圍。對不可達條件的恆真斷言不算防護證據。
- 核實 harness 上限、TestMain/共享庫、環境與真正命令；基線紅附原始輸出、歸屬與範圍，不能拿已知紅當豁免。命令/grep 判準有改就重算，需覆蓋全部 ownership。
- 重大守衛修正且測試已授權時，列規則→可觀察後果→對應髒 seed→自然錯誤變異。可手工備份、套變異、確認非空且非純註解 diff、跑指令、復原並核對 bytes；依 /verify 的手工循環，不依賴未部署 helper。無授權/工具時明列未驗，不假稱變異證明。

## 環境與並行

- 派工當下親驗 DB/服務/API 位址；不憑記憶、不讓工人自行起未知 infra。前端先核實地端 API 再送資料。
- 每個 coworker 附實際 cwd、branch/base/HEAD、執行命令、exit 與 log；實作者分開 worktree。大腦要改 in-flight ownership 先用 native API 協調或中止，不搶寫檔。
- 每份 brief 都有完成報告條款與提交權限；工具額度不足明示 fallback。環境、API 或結構與 brief 互斥即回報。

## 轉為裁示前

Facts 自己核對，runtime 斷言要實跑。把全部修正項與各審查軸一次列清；含輸入空間缺口的 MINOR 不能靠「小」豁免。外部輸入的每條取值路徑與查無/畸形行為都要查，不能只覆蓋正常主路徑。
