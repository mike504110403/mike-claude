# /mega — 大工程（先探路，再拆波）

## 入選標準（任一成立）

- 任務量一波 ≤5 工人派不完。
- 還有未決的技術決策（選型、架構、資料模型）。

## 流程

### 1. 探路段（決策先於實作）

- 把「要決定的事」列成 **decision 清單**：每項是一個問題，不是一個實作。
- 逐項用 討論（/office-hours、**/grilling——mega 必經**，把需求與每個決策烤到共識）/ 研究（/research，發現落檔 repo）/ 原型（/prototype，一次性驗證後即棄）解掉。
- **戰爭迷霧**：講不精確的問題不硬切，掛「尚未明朗」清單，等前面的決策解開再切。判斷標準是「問題能不能講得精確」，不是「現在能不能回答」。
- 決策結果依三條件落 ADR（新專案 `docs/adr/` Matt 格式；舊專案沿用 `.claude/decisions/`）。
- **Spec 定稿（拆波前的硬閘門，2026-08-20 起）**：全部決策解完後，把結論寫成 spec 檔落在專案 `docs/specs/<slug>.md`（隨 feature 分支 commit）：目標／範圍／非目標／行為規格／驗收總表／已決策清單（引 ADR）。**之後一切依 spec 開發**：邊界卡引用它、每波 brief 從它切片、brief-reviewer 拿它當上游對照物、跨 session 續作先讀它——大工程對抗長 session 的 ctx 漂移與幻覺，**靠檔案不靠記憶**。spec 改版要 Mike 點頭並記版次；波中發現 spec 錯 → 停波修 spec 再續，不得邊做邊改。

### 2. 拆波段

- spec 定稿、實作路線清楚 → 拆成多個 /feature 波次，每波獨立走 /feature lane 全流程（brief 從 spec 切片 → brief-reviewer → 派工 → 驗收 → review chain）。
- **拆分粒度**：波內任務盡可能拆細——一工人一單一意圖小切片，壓低每個 agent 的 context、讓它只聚焦自己那片；下限是下一條共用檔案硬規則。
- **拆波時每波標注依賴**：「依賴波 X」或「獨立」。判準除了邏輯依賴，還有一條硬規則：**兩波會碰同一個共用檔案就不算獨立**（共用元件與其消費者拆開會讓 reviewer 報幻影問題，跨波同理）。
- 每波回報帶進度重述：「N 波完成 M，下一步：X」。

### 2.5 波次 pipeline（兩層重疊，2026-08-11 起）

- **規劃層（無條件重疊）**：波 N 進入 review chain 或工人背景執行時，大腦即開跑波 N+1 的探路（背景 agent）與 brief 草稿。**閘門：brief 草稿必須等波 N review 收尾、對照打回結論修訂後才定稿派工**——review 常修正大腦自己的契約，跳過這一步等於把錯誤契約整批複製到下一波。
- **實作層（僅獨立波）**：標注「獨立」的波可在前波 review 期間直接派實作，各自依 /feature-flow 階段一開需求 worktree 並行（主 checkout 恆 dev 不切換）；依賴波的實作一律等前波合併回 dev 後才開。
- **合併回 dev 永遠由大腦按完成順序串行執行**，不並行。
- **波界節律**：每波合併回 dev 即更新 wip 看板快照＋**跑一次 `/cost` 把本波 token 數記進看板一行**（累積 2-3 波後供模型選配與力度調參用數據裁決）；**跨波續作優先開新 session**（讀 spec＋wip 起跑）——大腦 context 跨波累積會鈍化判斷，狀態已外部化，換新 context 成本近零。
- **多波並行時 wip.md 必須維護波次看板**（格式在 /wip），大腦寫任何註解／文件／裁示前先查表，不憑腦中狀態——大腦同時持有多條分支狀態時，「拿未合併分支的狀態當現況」是已知複發錯誤族。
- **反悔訊號**（出現任一 → 收窄回只重疊規劃層，並回報 Mike）：
  - 大腦犯分支狀態混淆族錯誤（寫錯現況進文件、合錯分支、驗錯對象）。
  - 獨立波實作連續兩次被前波打回連坐作廢（依賴判定不準）。
  - 工人隊列或大腦驗收開始積壓（並行度超過大腦吞吐）。

### 3. 跨 session 交接

- 專案根目錄維護 `.claude/wip.md`（已解決策、波次看板、下一步）；每波狀態轉換即更新，不等收工。
- 收斂與續作一律用 /wip 執行；工程完成即刪 wip.md（歷史在 decisions/ 與 git log）。

## 跳線

- 探路中發現整體其實不大（一波派得完、無未決選型）→ **問 Mike** 後降級 /feature。
- 執行波次中的個別任務跳線，依 /feature 的跳線規則處理。

## 回報格式

探路段：decision 清單現況（已解 / 尚未明朗）。執行段：依 /feature 五點回報＋波次進度。
