# /verify — done ≠ done 驗收

工人的回報只是宣稱，驗收看的是**檔案實況與 commit 內容**。

## 派工 lane（/feature、/bug 大修）四步

0. **（多需求／多波並行時）先查看板**：wip.md 有看板就先查——本次驗的是哪個需求、哪條分支、對照哪份 brief，不憑腦中狀態。單需求無看板則略過。
1. **確認 commit 存在**：`git -C <worktree> log --oneline -5`。要驗的是「即將被合併的那個 commit 裡有什麼」——用 `git show <branch>:<path>` 或 `git diff <base>..<branch>`，**不要 grep worktree 現況**（工作目錄可能有未 commit 的內容，合併進去的分支不含它）。
2. **範圍對帳**：`git diff --stat` 對 brief 範圍欄——多改的（scope creep）與少改的都要追。
3. **抽讀關鍵檔**：不信回報宣稱的規格版本，以 commit 內容為準。
4. **親跑可執行證據**：跑什麼**唯一依據全域 CLAUDE.md「改動面 × 驗證義務」矩陣**（本檔不重抄，防漂移）；指令形式與已知基線先查 ~/.claude/PROJECTS.md「驗證指令與已知基線」表——**基線只決定歸屬、不決定豁免**，基線紅照列順路發現，新增紅才擋驗收；表沒有的 repo 順手補一行。
   - 工人未附實際執行輸出，視同未完成。
   - 帶變異證明的：抽查時**選工人沒做過的變異**，一律用 `~/.claude/bin/mutate --file <檔> --sed '<替換式>' --test '<測試指令>' [--cwd <目錄>]` 一鍵跑完「備份→套變異→印 diff→跑測試→還原」——它內建三道踩過的坑防線：diff 為空判 FAIL（變異沒套上）、全註解變動警告（perl/sed 只換到註解的假陰性）、還原用 cp 備份絕不 `git checkout --`（未 commit 改動會被洗掉，2026-08-06 工人、2026-08-19 大腦各踩一次）。exit 0＝紅（防護有效）、4＝變異存活、3＝沒套上。腳本不可用時 fallback 手工循環，照同三道防線做。
   - **多工人同時待驗**：編譯級證據可 `run_in_background` 同時發起（同時最多 3 條，RAM 考量）——背景平行只重疊等待，**merge／進下一站前必須逐一讀回每個背景任務的完整輸出**，不看 exit code（下方 gate 紀律的 FAILED-but-exit-0 實例同樣適用）。

## 抽查深化

- **宣稱 vs 斷言對帳**：帶具名測試清單的交付，抽一條問「名稱宣稱的失效模式發生時，這個測試會紅嗎」；參數化測試檢查參數真的進入被測呼叫（迴圈變數沒人消費＝N 次跑同一份碼）。
- **變異防「自首型」**：抽查變異用「最自然的犯錯寫法」（不含配合測試的附加行）；工人的變異體若自帶配合測試的改動，重做。
- **「照搬／沿用」宣稱逐行對照參照物**：殘留的舊碼行為最容易躲在「沿用」裡。
- **修正輪多項指派**：驗收拿**派工訊息**當 checklist 對 diff 勾稽，不拿工人自己的對照表當底（工人只對照自己記得的清單）；要求工人回報開頭原樣複列全部指派項、逐條標狀態。
- **接手他人未完成工作**：把「既有註解宣稱的保證」列為待驗項逐條驗，不只跑 build/test。
- **跨交付物時序**：多工人交付疊起來的部署劇本，照 runbook 桌面推演走一遍——單件驗收擋不住「各自正確、疊起來必炸」。
- **oracle 正確性不能靠變異**：變異只證明「測試釘住了公式」，不證明「公式是對的」——用真實輸入形狀的實例手算對一次。

## 直改 lane（/quick、/solo）裁剪

沒有工人回報，1-3 免；自我 `git diff` 過一眼範圍 ＋ 執行第 4 步親跑證據。

## 操作紀律

- **gate 指令不鏈複合指令**：「跑測試 → merge」分開下、看完結果再走——測試印 FAILED 但 exit 0 時 `&&` 擋不住。
- git 一律 `git -C <絕對路徑>` 顯式指路徑。
- 不符 → 重寫 brief 重派，並記退件（全域退件迴饋迴路：memory/rejection-log 一行）。

## 通過之後

派工 lane → 呼叫 /review-chain；直改 /solo → 呼叫 /review-chain；直改 /quick → 不 review，直接收尾。
